# Comparación de plantillas y herramientas

## Opciones evaluadas:
- SRS IEEE
- Historias de Usuario


| Criterio | SRS IEEE | Historias de Usuario | Evaluación |
|---|---|---|---|
| Claridad | Presenta requisitos detallados y estructurados. | Describe necesidades de forma sencilla. | SRS gana para documentación formal. |
| Nivel de detalle | Alto nivel técnico. | Menor detalle. | SRS es mejor para proyectos académicos. |
| Gestión de cambios | Usa versiones y control documental. | Permite cambios rápidos en backlog. | Historias de usuario son más flexibles. |
| Comunicación con usuarios | Puede ser más complejo. | Fácil comprensión para usuarios. | Historias de usuario tienen ventaja. |
| Trazabilidad | Usa IDs y secciones organizadas. | Relaciona tareas y pruebas. | Ambas permiten seguimiento. |
| Adaptación al proyecto | Ideal cuando existen muchos requisitos. | Ideal para equipos ágiles. | Depende del tamaño del proyecto. |


## Recomendación final

Para el Sistema de Citas Académicas se recomienda combinar ambas técnicas. 
El documento SRS permitirá mantener una documentación formal del sistema, mientras que las historias de usuario facilitarán la comunicación con estudiantes y docentes durante el desarrollo.
